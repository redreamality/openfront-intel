## 直接答案：复盘第一个失效的假设，不要只看最终名次

从公开 profile 的 Games history 打开已结束对局，先复制 game link，再扫一遍 Stats，并只复盘三到五个转折点。每个转折点都记录当时知道什么、选择了什么、预期什么、实际发生什么，以及计划最先被哪个信号推翻。把结论标为“已观察”“可推断”或“未知”，最后只改一个下一局动作，并写清触发条件与停止线。

这就是回放复盘的完整目的。它不是被动看录像，不是等到赢家明显后才挑一处失误，也不是用终局画面嘲笑导致最后一块领土丢失的操作。真正有用的复盘要向前找到仍由自己控制的最早决定。若西线在第十八分钟崩溃，关键点也许是第六分钟没建的 City、第十一分钟忽视的联盟提醒，或第十四分钟接受的第二条战线。结果只告诉你故事怎样结束，回放负责检验原来的假设何时改变。

OpenFront `v0.34.1` 把证据路径连成一条线。Profile 对外公开，Games history 能列出完成的比赛，history card 可以打开 Stats、复制普通 game link 或启动 Watch Replay；回放的 spectator 状态还能打开玩家信息面板。旧对局在相应 shell 存在时可以转到版本化回放。必须保留历史边界：可分享 profile 与历史在 v0.33.13 已有正式说明，旧版本回放在 v0.33.6 已有说明，不能把所有能力都写成 v34 首发。本页以 v0.34.1 为当前核验边界，是因为正式 Release 与不可变 tag 能证明这些能力现在怎样协同工作。

本页只负责赛后方法。[第一局攻略](/zh/guides/first-match/)负责玩家第一次实时对局怎样操作；[威胁评估](/zh/guides/threat-assessment/)负责新攻击前怎样扫描当前地图；[败局恢复](/zh/strategies/recovery-playbook/)负责已经落后时怎样稳住局面。回放复盘从比赛结束后开始，回答哪个判断失效、哪个反应当时可见、下一局应该用哪个单变量实验验证。它可以分析开局、贸易、联盟、陆战、核战、翻盘与异常协作，却不会取代相应主题的机制答案。

每条因果判断旁都放一个证据标签。“已观察”表示回放、玩家面板、history card 或 Stats 直接显示；“可推断”表示时间顺序支持这个解释，但界面没有展示真正原因；“未知”表示现有证据无法区分几个合理解释。回放可以显示四名玩家反复转移资源或按顺序进攻，却不能单独证明他们私下协调、作弊、怀有某种意图，或看到了另一块屏幕上的内容。这个限制不是结论后的礼貌措辞，而是防止后见之明制造假确定性的核心步骤。

完成标准是一句可复核的话，例如：“当相邻领先者投入第二条战线，我只测试一次有边界的推进；出现新边界或预备队低于最近稳定值就停止；下次回放检查我是否在第一个失效信号处停下。”“应该更激进”没有触发、范围与可观察结果，不能算结论。一局比赛只能提出假设，下一局才是第一次尝试推翻它。

## 找到准确对局，并在播放前保存证据

从 profile 开始，不要从记忆里的精彩片段开始。v0.34.1 客户端可以在无需查看者登录的情况下请求公开 profile 与分页 Games history。Profile 可用包含 public identifier 的完整 URL 分享，并提供 Stats、Games 与 Clans 标签。进入 Games，选择已结束对局，在碰回放控制前先抄下卡片信息：地图、日期、结果、Clan tag、用户名、对局类型、玩家数与时长。它们共同定义本次案例；“那局岛图”或“那场大型 FFA”太模糊，无法和下一局比较。

立刻复制 game link。History action 复制当前站点的普通对局路由；已知 worker 时通常形如 `/w15/game/<id>`，否则为 `/game/<id>`。不要自己拼 `replay.` 主机名。普通路由会先加载归档记录；当记录的 `gitCommit` 与当前客户端不一致，客户端才可能探测对应版本化 shell，并且只在收到成功 HTML 响应后跳转。二者职责不同：普通链接是你和另一位复盘者共同打开的证据；版本化 shell 是有条件的基础设施，不保证所有历史 build 永久存在。

播放前写一个窄问题和它的重要性。“我为什么输”会制造无边界搜索，任何尴尬画面都能被挑成答案。“北方联盟出现到期提示后，西线攻击何时失去保护”明确了关系、路线与失效事件。“三座 Factory 是否帮助恢复，还是施工顺序暴露了唯一相连的 City”明确了投资与生存结果。一个问题应由一条时间序列回答。途中发现别的问题时放进候选清单，不要偷偷更换本轮目标。

然后打开 Stats，但把排名当定位器，不当裁决。固定 tag 的单局视图可以展示地图、开始时间、时长、玩家数等概览，以及 survival、conquests、Atoms、Hydros、MIRVs、Total Gold、Stolen Gold、Naval Trade、Train Trade 与 Conquered Gold 等排名。高 Total Gold 不能证明消费正确；conquests 多不能证明进攻时机正确；Train Trade 高也不能指出哪一站改变了局势。排名只告诉你哪里值得看，因果仍在时间线上。

按下播放前选三到五个 waypoint。常用候选是出生承诺、第一次争夺扩张、第一笔重要建筑投资、首次联盟或背叛、第一次核投入、首次严重失地，以及最终联盟不可避免的时刻。只保留和问题有关的节点。一场三十分钟比赛若全程用相同注意力观看，只会变成另一段模糊记忆；预先选点才能形成可比较记录，也方便第二位复盘者复现。

每个 waypoint 都保留两列。“当时已知”只能写玩家当时合理可见的边界、通知、联盟、当前资源、可见建筑和活动进攻。“回放可见”写赛后 spectator 视角能检查的更完整状态。绝不能把回放专属信息搬进第一列，好让旧决定显得愚蠢。这个分界允许更准确的判断：某个决定开始时合理，但在一个公开警告后变得错误。这样的诊断远比“因为后来输了，所以整个计划都错”更能指导下一局。

## 用 TRACE 把时间线压缩成一个可证伪改动

`TRACE` 是本站用于复盘的编辑框架，不是 OpenFront 的游戏机制。五个字母分别要求你 **Target 定位时刻、Reconstruct 重建状态、Audit 审计证据、Classify 分类原因、Edit 编辑一个改动**。每个预选 waypoint 都按同一顺序走一遍。重复同一标准很重要：赢家的选择不能因为结果好就获得宽松解释，输家的选择也不能因为终局难看就被要求拥有当时看不到的信息。

**Target** 要写出准确决定和预期收益，不要只写情绪。例如：“Blue 正在北边交战，所以我在西线送出第二波，预期在联盟到期提示结束前拿下 Port。”句子里必须有地图对象、可见触发和期望结果。若一时找不到决定点，就从明显损失向前倒放，直到找到最后一次仍有替代方案的时刻。目标通常不是“最后一战”，而是那次让下一条安全路线消失的投入。

**Reconstruct** 要形成一句状态陈述。记录当时可见的资源、相连领土、开放边界、活动冲突、受威胁建筑、联盟与到期警告，以及可能介入的玩家。接着写出把这些事实连起来的假设：“Blue 在我完成占领前无法转向”，或“升级 Port 后这条贸易路线仍会存在”。在假设第一次变成错误时暂停，那就是失效信号。它可能是新边界、通知、运输船起航、联盟倒计时、敌方建筑或资源跌破某条线。信号比最终伤害更适合带到下一局。

**Audit** 用回放地图、玩家信息面板与 Stats 交叉核对。Spectator 状态能打开被选玩家的只读信息路径，而不是普通实时操作盘；面板可以暴露该回放时刻的身份、资源、统计、联盟、背叛次数与交易状态。只记录真正显示的项目。看不到的数值就标为未知，不能用记忆、视频自动字幕或最终排名补空。最终排名可用于发现异常高的资源、占领、贸易或核武指标，但发现后仍要回到该指标开始影响局势的确切时刻。

**Classify** 同时给证据和错误分类。证据只能是已观察、可推断、未知；最早可控制的断点可能来自规则误解、测量错误、时机错误、地图或模式限制、对手适应、控制范围外的协作，或者运气。可以有多个贡献因素，但必须选择一个主要断点。把一切叫作运气会忽视公开警告，把一切叫作水平差则会惩罚当时没有信息的合理选择。分类的目的，是把可训练技能与后见叙事分开。

**Edit** 把断点写成单变量实验：“当 **信号** 出现，我执行 **一个动作**，直到 **停止条件**；下一次回放以 **一个可观察结果** 判断。”改动必须小。一次同时改变出生、建筑顺序、进攻比例、联盟政策、预备队和贸易对象，只会产生一个无法归因的新故事。可用实验包括限制第一波、延后一座建筑、在联盟提示时重新扫图，或保留一条相连退路。即使下一局获胜，同一 waypoint 仍可能推翻这个实验。

只有另一位复盘者能打开同一链接、找到同一 waypoint、理解哪些事实当时可见，并说出什么证据会推翻你的结论，TRACE 才算完成。对方不必同意主要原因；可审计性才是要求。第二位玩家可以把同一事件归为对手适应，而你归为时机错误，但双方都应指向同一警告，并说明下一局实验究竟测量什么。

## 场景一：在领土崩溃前找到过度投入

假设这是一场 Greece 地图、65 人 FFA。时间线借用已核验社区视频中的局势类型，但不把视频里的个别操作当成机制证明。02:00 时你在低密度区域，用有边界的 10% 推进并考虑包围。06:00 时你拥有一座 City 和一座 Factory，北方边界有联盟，西方对手正在向南交战。你认为路线暂时便宜，于是启动更大的西线攻击。10:00，第二名玩家接触到你新获得的海岸；14:00，北方联盟出现到期提示；18:00，你仍向西增援，预备队低于 06:00，地图上又出现核威胁；22:00 才发生显眼的领土崩溃。

只看成绩的复盘会从 22:00 开始，并断言核武导致失败。TRACE 要更早定位 06:00 的西线承诺：预期收益是在守方恢复前完成短距离占领。重建当时状态可发现，对手确实忙于其他战线，北方联盟仍有效，City 与 Factory 相连，而且第二条海岸边界尚未打开，因此第一次试探可能合理。第一个失效信号在 10:00 出现：新玩家抵达海岸，既增加潜在介入者，也改变必须防守的几何形状。14:00 的联盟提示是第二个、更响亮的信号。任何一次之后继续增援，都需要新假设，而不能自动沿用 06:00 的许可。

在 06:00、10:00 与 14:00 分别审计相关玩家。只抄面板真正显示的资源、联盟、交易状态和统计；查看最终 conquests、Total Gold、核武或贸易排名，只为决定哪段时间线值得再看。不能因为 Gold 排名高就证明 Factory 投资正确，也不能因为后来出现 MIRV 就倒推早期攻击必然错误。时间线能支持的因果结论更窄：海岸打开后，进攻失去了开始时假设的单线保护，而增援跨过了两个公开的重新扫图信号。

把主要断点分类为时机问题，地图形状与对手适应是贡献因素。这不一定是规则误解；错误在于把一次有效试探当成路线变化后仍永久有效的增援授权。海岸打开和联盟提示标为“已观察”。“第二名玩家一直在等我投入”只能标为“可推断”，因为时间线不暴露其意图。任何关于私下协调的判断都标为“未知”。

下一局只编辑一个动作：“当主动推进获得的土地让新玩家变得可达，我立即停止增援并重扫所有活动边界；只有原预备队仍相连，而且即将到期的联盟已有明确应对时才恢复。”可观察结果不是最终获胜，而是第一波是否在第二条战线消耗预备队之前结束。建筑顺序、出生选择与联盟政策尽量不变，这样回放才能判断停止信号是否改善了决定。

对手可以反制这个实验：用一次很小的靠近诱使你廉价停手，把压力藏在联盟后面，或等扫图结束后再进入。它们不会自动使规则无效，而会要求下一次回放区分“接触”与“投入”。记录新边界是否形成真实路线、对方力量是否持续，以及停手是否保留了有用选项。纪律性停止即使放弃便宜领土也可能正确；一次继续推进并获胜，也不能证明它可重复。

## 场景二：把可重复翻盘与促成翻盘的大厅条件分开

假设你在一场漫长 FFA 中先被压缩到狭窄、近乎断开的区域，最后却取得第一。History card 显示对局持续 48 分钟，回放里看似有三项恢复动作：保住一座 Factory、接受第三方贸易、在重新扩张前建 SAM。最终排名又显示很高的 Train Trade 和多次 conquests。最诱人的结论是把它写成胜利配方：“快被淘汰时建 Factory 和 SAM，等待，然后扩张。”已核验 Reddit 翻盘讨论说明这个故事过于简单；原作者也把成功归因于领先者互战、第三方贸易、对手忽视幸存者、濒死对手过度投资，以及运气。

使用两本账。可控制账记录焦点玩家自己的选择：保留相连建筑、最弱阶段不主动攻击、接受或维持贸易路线、面对可见核威胁时防守，以及选择第一次有边界的重返陆地。促成条件账记录他人制造的窗口：两名领先者互相消耗、贸易伙伴继续转移资源、对手选择别的目标、价值路线仍保持开放。每个条件出现时都暂停。只有能说出让动作合理的可见信号，它才进入下一局实验；不能由自己控制的条件只能进入扫图清单。

假设回放显示：12:00 时 Factory 幸存但没有安全站点链；16:00 第三方开始贸易；20:00 两名领先者开战；25:00 看到 Silo 后你增加 SAM；31:00 你沿一名领先者放弃的陆地重新扩张。TRACE 不会根据最终排名分配因果功劳。定位 31:00 的重新进入，重建当时已知：两名领先者仍在交战，路线已经开放十一分钟，防御建筑覆盖幸存核心，背后没有立即形成新边界。在 20:00、25:00 与 31:00 审计资源和联盟，把领先者冲突与贸易归为促成条件，把 SAM 时机归为对已观察威胁的响应，把有边界的重新进入归为可控制决定。

下一局实验必须保持这个边界：“当两个更强且可达的玩家仍彼此投入，而且我的相连核心已安全度过一个完整复查间隔，我只向被放弃的路线测试一次扩张；任何领先者脱离战斗或路线形成第二条活动边界就停止。”不要加入“必须建三座 Factory”、固定等待分钟数或必然翻盘。这些数字无法由一条回放建立。实验只检验等待可验证冲突、同时保留一个出口，是否改善生存选项。

再加一个异常变体。回放可能显示四名附近玩家按顺序进攻，或反复把贸易转向同一接收者。用复制的 game link 保存位置、时间戳、转移、关系变化和合理替代解释。顺序本身可标为已观察；除非还有其他证据，“他们在游戏外协调”仍是未知。回放适合支持中性事实报告，却不能读取私聊或意图。异常协作可能是主动计划、局势自然形成、互利选择或巧合，严谨标签同时保护分析质量与公平。

两个变体的完成条件相同：另一位复盘者能把你的动作与促成它的条件分开，指出最早可控制选择，并说明未来哪个事件会推翻这条经验。依赖对手忽视的翻盘仍值得研究，只是它教的是“识别并保护窗口”，而不是“这套建筑顺序永远会赢”。

## 审计 Stats 与回放面板，不要把它们变成判决书

Profile、history card、Stats、地图和回放玩家面板分别回答不同问题。Profile 识别公开身份并提供历史入口；card 固定对局背景与可用动作；Stats 汇总结果；地图显示事件顺序；玩家面板展示被选玩家在某个回放时刻的状态。问题通常发生在用一层证据回答它无权负责的问题：最终排名无法解释一次联盟决定，一张截图不能建立此前的资源趋势，公开 profile 也不能证明某一时刻究竟是谁控制账号。

使用简短审计表，并在观察旁直接写明限制：

| 证据界面 | 适合回答的问题 | 不安全的结论 | 复盘用途 |
|---|---|---|---|
| History card | 哪一局、什么地图/类型/日期/时长/结果？ | 结果本身暴露决定性错误 | 定义案例并保存链接 |
| Game Stats | 哪个结果分类异常高或低？ | 高总量证明时机正确或存在因果 | 选择要检查的时间段 |
| 回放地图 | 边界、冲突和可见威胁何时改变？ | 地图能揭示私人意图 | 定位信号与响应 |
| 玩家面板 | 当前暴露哪些资源、联盟、贸易、背叛或统计？ | 所有隐藏数值与动作都可见 | 交叉核对 waypoint |
| 公开 Profile | 哪些结束对局关联此公开身份？ | 历史能证明动机、水平或违规 | 查找可比较案例 |

固定 tag 下的回放路径属于 spectator 状态。在玩家格上右键可以进入只读玩家面板路径，而不是普通实时 action radial；正常的服务器意图动作不会走该 spectator 分支。这证明存在复盘界面，却不代表全知。当前 tag 没有为每一个玩家面板字段和动作提供专门 replay-mode 单元测试，因此只记录眼前 build 真正渲染的内容。不要承诺每个菜单动作必然消失、每项统计都能还原到每个 tick，或 moderation 流程拥有同样边界。

排名尤其需要克制。Survival 可把你带到恢复片段，conquests 可定位连续推进，Atoms、Hydros 与 MIRVs 可定位核阶段，Total Gold、Stolen Gold、Naval Trade、Train Trade 与 Conquered Gold 可提示经济问题。但它们都不回答消费是否及时、路线是否安全，也不回答玩家当时是否知道威胁。先用排名选 waypoint，然后回到状态、决定、预期、响应与第一个失效信号。

警惕四类复盘失败。**结果偏差**把所有获胜选择判为正确、所有落败选择判为错误；**后见泄漏**把回放可见信息塞进“当时已知”；**指标替代**用最方便引用的排名替换原复盘问题；**叙事叠加**在一局后同时改变五种行为，下一局赢了又把功劳给最喜欢的那一项。TRACE 通过保存原假设、标记证据和只编辑一个变量来限制它们。

对手行为也限制归因。对方可能故意展示假窗口，只投入足够资源诱发响应，用联盟中断核序列，或撤退来拉长你的边界。复盘不应追求消除所有不确定，而应找出哪项不确定当时可见，以及你能采取什么可撤销动作。若根本没有可靠信号，正确标签可能是“未知”，而不是“失误”。把这种局保留为反例；不是每次落败都包含可修复错误。

## 尊重地图、模式、版本、隐私与可用性边界

一条经验只有在环境被写明后才能迁移。比较两局前，记录地图、对局类型、玩家数、时长和所有可见模式规则。岛图回放更强调水路入口、Port 生存、运输路线以及谁能进入同一地块；狭窄大陆走廊更强调边界数量和 Defense Post 几何；拥挤 compact 地图缩短反应时间并让第三方更早接触；大图可能保留更长窗口，却隐藏远处介入者。“更早扩张”在这些形状上绝不是同一个动作。

模式也会改变证据。Team 中单看一名玩家似乎浪费的投入，可能是在保护队友路线或完成共同目标；应复盘团队状态和谁能增援，而不是只看焦点玩家排名。FFA 中临时合作与共同敌人可以制造同步攻击，却不等于正式组队。Singleplayer 的暂停与较少外部协调会改变执行压力，private lobby 又可能关闭单位或调整设置。在说明关系、胜利、单位与时机假设哪些仍等价之前，不要跨模式比较动作。

版本是案例的一部分，不是装饰性 metadata。v0.33.13 已记录公开、可分享 profile 与 game history，v0.33.6 已记录旧版本对局回放；v34 后来把公开 profile 政策、history card 上的 game-link 按钮与支持回放的玩家信息面板连成当前路径。当归档记录的 `gitCommit` 不同于当前客户端，应用可以探测 `https://replay.<audience>/<gameId>`，仅在有效 shell 响应时跳转；shell 不存在时会保留 mismatch 状态。因此应保存普通 game link 并让客户端路由，绝不能承诺每个历史 build 都永久可回放。

该边界也影响战略结论。旧 build 的攻击平衡、胜利门槛、核武时机、AI 行为、地图池或界面信号都可能不同。只有核对对应版本规则后，旧回放才适合研究某个决定。不要用 v0.34.1 建议倒推 v33 选择“不理性”。若相关机制已变，打开相应版本文章或当前主答案，并把旧对局标为历史。[v34 版本笔记](/zh/changelog/v34/)负责当前稳定边界，[陆战](/zh/guides/land-combat/)与[加时胜利](/zh/guides/winning-overtime/)等主题页负责真实规则解释。

隐私必须明确，因为 v0.34.1 正式 Release 说明 profile 公开，任何人都能查看玩家 games，也说明删除账号是隐藏所有对局的方式。客户端代码确认公开 profile/history 请求和可见字段，却无法证明后端删除时机、数据保留周期或所有脱敏细节。只分享复盘所需的 game 或 profile link，避免重新发布个人信息，不要把战略文章变成指控记录，也不要暗示公开比赛等于放弃一切隐私顾虑。

可用性同样有条件。History 使用不透明 cursor 分页，schema 不承诺固定页数或永久时间范围；game link 以后也可能依赖从未归档的 shell，网络或部署状态会中断原本有效的路线。链接旁保留一份简短文字账，确保证据失效后经验仍存在。不要为了绕过正常访问去下载或抓取私人数据。真正有价值的是带边界的事件序列，不是永久镜像别人的历史。

最后，要预期对手与复盘者意见不同。两名复盘者可以接受同一条已观察时间线，却选择不同主要原因。比较第一个失效信号和拟议实验，不要比语气或自信。只要规则、地图、模式、版本或可见性边界改变了信号含义，结论就应该随之改变，这正是证据正常工作的表现。

## 保留复盘账、测试一个改动，再回到负责该问题的攻略

每次复盘都使用相同七列。稳定表格能让两局真正可比较，也能防止最新故事覆盖旧假设。

| 时间或事件 | 当时已知 | 回放可见状态 | 决定与预期 | 实际结果 | 证据标签 | 下一局改动 |
|---|---|---|---|---|---|---|
| 出生或第一次承诺 |  |  |  |  |  |  |
| 第一次争夺扩张 |  |  |  |  |  |  |
| 第一次联盟或背叛 |  |  |  |  |  |  |
| 第一次严重过度投入 |  |  |  |  |  |  |
| 决定性终局变化 |  |  |  |  |  |  |

从 history card 建账。单独保存 game link，再记录地图、类型、日期、时长、玩家数与结果。打开 Watch Replay 前先写问题，只填三到五行。“当时已知”排除 spectator 才能看到的内容；“回放可见状态”应指明地图、玩家面板或 Stats 分类，不写含糊的“显然”；证据标签只能选已观察、可推断、未知。直到找到最早可控制断点，最后一列都保持空白。

严格按这个句式写实验：“当 **信号** 出现，我执行 **一个动作**，直到 **停止条件**；以 **一个可观察结果** 判断。”若复盘发现新海岸打开后仍持续增援，动作可以是重扫一次并冻结增援，停止条件可以是预备队跌破此前稳定值，结果则看第一波是否在第二活动战线形成前结束。不要同时改开局、建筑、联盟与攻击比例；在真实大厅允许的范围内保留其他变量。

下一局结束后，即使获胜也复查同一 waypoint。确认触发是否出现、动作是否执行、停止条件是否触发，以及预测结果是否跟随。触发从未出现的一场胜利不能验证实验；一场失败若该动作保留了第二个选项，仍可能支持它。记录反例，不要隐藏。两三个可比较案例可以磨利个人规则，却仍不足以制造通用机制。

然后回到负责失效输入的页面。目标选错或漏看第三方时看[威胁评估](/zh/guides/threat-assessment/)；已经接触但投入、密度、路线或预备队失败时看[陆战](/zh/guides/land-combat/)；Gold 分配或容量是限制时看[经济基础](/zh/strategies/economy-fundamentals/)；关系时机改变路线时看[外交与背叛](/zh/strategies/diplomacy-betrayal/)；只有复盘走到 MIRV 之后的几分钟，才看[MIRV 后恢复](/zh/guides/post-mirv-recovery/)。回放攻略诊断问题归属，主题攻略提供规则与决定方法。

本文证据边界是 2026 年 9 月 15 日核验的 OpenFront `v0.34.1`。正式 [v0.34.1 Release][release]建立公开 profile 政策并承载 v34 玩家功能；固定 tag 的[profile history][history]、[单局 Stats][stats]、[回放玩家面板][panel]、[版本化回放路由][versioned]与[版本化回放测试][versioned-tests]证明界面行为及限制。来源包中的社区讨论与带字幕视频证明玩家希望打开旧版本、分享准确对局、区分过度投入与坏运气、分析翻盘和描述异常合作；它们不证明机制、意图或最优玩法。

结束时给复盘伙伴发送 game link 与唯一实验，不要发送判决。优秀复盘即使遭到不同意见仍有价值，因为时间线、证据标签和停止线都能检查。下一局应该回答一个比上一局更小的问题，这样公开 history 才会变成练习，而不是围观。
