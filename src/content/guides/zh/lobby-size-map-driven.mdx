**简短答案。** v0.35 移除了排程公开大厅固定的 125 人上限，大厅规模现在由地图的地块面积推导。The Box 的大型自由对战可容纳 210 人（团队模式 158），Alps 可达 185（团队 143）；中东与 Two Lakes 达 170，Mare Nostrum 130。自由对战通过一次掷骰在三个规模档中取一，团队模式再把该基础值乘以 1.5。在当前的稳定版 v0.34.25 上，每个大厅仍被硬性限制在 125 人，因此这些数字只出现在 v0.35 测试版上。

## 实际发生了什么变化，以及影响哪些大厅

理解这次变化最关键的一点是它的范围，因为玩家很容易把“大厅变大”读成“所有大厅都变大了”，而事实并非如此。在当前的稳定版 v0.34.25 上，服务器为每一个排程公开大厅——那些由主调度器从地图播放列表填充的自由对战、团队与特殊大厅——计算一个目标玩家数，然后用最后一行代码把该数字强行压到 125，这是一条适用于所有大厅的性能上限，与地图无关。无论地图能容纳 125 还是 210 人都一样，这条上限只是把所有数字钳制到同一个值。这条上限位于规模算法的最后一行，它不在乎地图是否真的能装下 125 人；它只是把所有东西钳制到同一数字。v0.35 的这次改动（跟踪在 PR #5548）彻底删除了这条最后的钳制行。规模算法现在停在由地图地块面积算出的值上，剩下的唯一上限就是该地图自己的最大规模档。所以这次变化不是模糊意义上的“大厅可以更大”，而是“那个一直在悄悄把所有大厅压在 125 的东西消失了，地块足够大的地图现在能显示完整规模”。

这个范围细节正是让变化成为真正决策输入而非装饰性数字的原因。受影响的只有排程公开队列——游戏替你运行的自由对战、团队与特殊队列——因为这些才会经过规模算法。托管队列不同：那是玩家自建并对外公开的房间，房主自己设定玩家上限，一直都在十到一百的范围内，由托管规则而非本算法管理。如果你加入的是托管大厅，这次变化完全不适用。地图一侧，这次增大是纯加法：一张地图的完整规模若原本就低于 125，就不会变得更大，因为它从来没真正触及旧上限。唯一可见变化的，是那些地块丰富、最大规模档现在会超过 125 的地图。实际含义是：你不该期待在小岛地图上体验到不同的大厅，但在 The Box 和 Alps 上尤其如此，游戏现在能给你一个比稳定版任何时刻都显著更大的自由对战，而这个更大的大厅会改变你从第一分钟起如何布防、扩张和投入。把范围按这种方式理解——哪些队列、哪些地图、以及它是加法——是本指南后续所有决策的基础，也是把线上稳定行为与新版行为区分开的版本边界。

## 新规模如何由地图地块计算

上限移除之后，你实际得到的数字是一个小公式的输出，了解它有助于你既理解每张受影响地图的规模，也理解同一张地图两个大厅之间的差异。每张 OpenFront 地图都有一个固定的地块数，即非水地块的总数。游戏取这个数并转成一个基础值：把地块数乘以每百万地块 50，把结果四舍五入到最近的 5 的倍数，且基础值最低不低于 5。这个基础值就成为该地图的最大规模档。从这个单一基础值出发，游戏再通过把它乘以 0.75 得到中等档、乘以 0.5 得到小档，并把每个值同样四舍五入回最近的 5 的倍数。因此一张地图的三个规模档不是三个独立数字，而是一个由地块驱动的基础值和它的两个比例派生值。这就是为什么任何地图的三档总是保持可预测的比例（大约 100 比 75 比 50），也是为什么最大档是判断“这张地图能否撑住一个大厅”的关键。

基础值之所以由地块数推导，是因为地块是玩家扩张所需的稀缺资源，而旧系统完全无视一张地图到底有多少这样的空间。一张有四百万地块的地图，容量大约是一张有一百万地块地图的四倍，所以在大地图上把大厅钳在 125 意味着大部分空间被闲置，而小地图在同一 125 下却真的拥挤。由地块推导基础值，把大厅规模与真实可玩空间绑定起来，让更大的大厅落在能容纳它的地图上。对受影响地图，数学是这样算的：The Box 约 419 万地块，产生 210 的基础值和 210、160、105 三档；Alps 约 367 万，产生 185、140、95；中东与 Two Lakes 约 340 到 345 万，产生 170、130、85；Mare Nostrum 约 264 万，产生 130、100、65。这些数字没有一个是随意或手调的；每个都是四舍五入后的地块驱动基础值及其两个派生值。理解这个公式，能让你预测任何地图的规模，也让你明白为什么同一张地图每分钟可能显示出非常不同的大厅人数——这正是下一节要讲的东西。

## 变化的五张地图：新旧对照

下表是这次变化的核心，也是最有用的一个工具：它显示五张完整规模现在会超过旧上限的地图在自由对战与团队模式下的规模变化。自由对战列列出该地图可能掷到的三个规模档（从大到小），团队列则给出这三个档各自的团队模式规模。“旧”值是稳定版 v0.34.25 的输出，125 上限把最大档和团队数字压平了；“新”值是 v0.35 移除上限后的输出。

| 地图 | 自由对战 旧 | 自由对战 新 | 团队 旧 | 团队 新 |
|---|---|---|---|---|
| The Box | 125 / 125 / 105 | 210 / 160 / 105 | 125 / 125 / 125 | 210 / 210 / 158 |
| Alps | 125 / 125 / 95 | 185 / 140 / 95 | 125 / 125 / 125 | 185 / 185 / 143 |
| 中东 | 125 / 125 / 85 | 170 / 130 / 85 | 125 / 125 / 128 | 170 / 170 / 128 |
| Two Lakes | 125 / 125 / 85 | 170 / 130 / 85 | 125 / 125 / 128 | 170 / 170 / 128 |
| Mare Nostrum | 125 / 100 / 65 | 130 / 100 / 65 | 125 / 125 / 98 | 130 / 130 / 98 |

逐列读这张表能告诉你谁受到影响。在自由对战列中，最大档对所有地图都跳升：The Box 从 125 到 210，Alps 从 125 到 185，中东与 Two Lakes 从 125 到 170，Mare Nostrum 从 125 到 130。中等档和小档大多不变，因为它们本就在旧上限之下，所以差异集中在最大档。在团队列中，模式更锐利：The Box 的团队大厅在稳定版的每一档都是 125，在 v0.35 的每一档都是 158，这是一次与掷骰无关的 33 人提升。真正在最大自由对战档上明显超过旧上限的两张地图是 The Box 和 Alps；中东、Two Lakes 与 Mare Nostrum 现在只是按比例而非被钳制，所以它们现在是“由地图驱动”的，但原本就已基本达到或略低于旧数字。这张表的实际读法是：如果你想要真正更大的大厅，要瞄准的两张地图是 The Box 和 Alps；如果你只想要正常规模的游戏，其余三张会感觉和过去差不多——这正是后文地图选择决策的关键输入。

## 掷骰如何决定你的规模

你在某张地图上实际得到的规模并不总是最大档；调度器为它打开的每个大厅掷一次随机骰，这次掷骰选出大厅使用三档中的哪一档。掷骰有三种结果：大约三分之一时间选中大档，三分之一时间选中中等档，略不到一半时间选中小档。因为掷骰均匀且对每个大厅独立，同一张地图上一分钟前后打开的两个大厅可能合法地拥有非常不同的玩家数，同一张地图也可能在这个大厅感觉小、在下一个感觉大。这就是为什么你会看到 The Box 在一个自由对战里是 210、在另一个里是 105，也是为什么“该加入哪个大厅”这个问题现在多了一个必须在点击前读取的尺寸维度。掷骰不是游戏替你做的一次选择，也无法在事前看见；它在大厅打开的瞬间发生，这意味着你能可靠读取结果的唯一时刻是公开浏览器，那里的大厅卡片显示了掷骰落定的数字。这一事实重排了你的工作流：你不再假定地图意味着规模，而是先在提交前读取规模，地图选择和掷骰共同——而非仅地图——决定了你即将加入的大厅。

对玩家而言，它体现在公开浏览器大厅卡片上的当前玩家数上，这个数字告诉你大厅落在哪一档。在 The Box 上，大掷骰意味着 210 名玩家，一个战线密布的自由对战，同时战线很多，早期扩张更慢，因为地块分散在更多对手之间；中掷骰是 160，感觉像经典 125 大厅但稍宽裕；小掷骰是 105，本质上就是旧上限减二十。在 Alps 上同一逻辑给出 185、140、95，在中东与 Two Lakes 上给出 170、130、85。最大档与最小档之间的差距正是这次变化真正的所在：在 The Box 上，差距现在宽达 105 人，从 210 到 105，所以落在大掷骰与小掷骰之间的差别比整个旧大厅还大。这是一个很宽的分布，正是它让规模成为需要规划的一等要素，而非固定常量。实际动作是在加入前读取浏览器中卡片的玩家数，这样你知道自己即将跳进一个 210 人的战线密布局还是 105 人的经典局，然后判断它是否匹配你想玩的。如果你想要大体验，就在浏览器里扫一个大档大厅并等它打开；如果想要正常的，就跳过大档卡片。因为每次大厅打开时掷骰都独立，你想要的规模等待时间实际不长，而浏览器是唯一能在点击前确认它的位置。

## 团队模式：1.5 倍乘法与钳制

团队模式使用相同的规模档，但最后一步不同，而这正是这次变化产生最令人惊讶数字的地方。掷骰仍然从地图选出一个基础档，与自由对战完全一致，但团队模式随后把该基础档乘以 1.5 并向上取整，因为团队大厅需要更多总玩家来填满同样数量的有意义队伍。还有一个第二步骤，把结果钳制到不超过该地图的最大档。对受影响地图，这个钳制通常不是约束，但理解它对读表很重要。在 The Box 上最大档是 210；大掷骰给基础值 210，乘以 1.5 是 315，钳到 210，所以大掷骰团队大厅是 210。中掷骰给 160，乘以 1.5 是 240，钳到 210，所以中掷骰团队大厅也是 210。小掷骰给 105，乘以 1.5 是 157.5 向上取整到 158，低于 210 钳制，所以保持 158。这就是为什么表中 The Box 的团队列显示 210、210、158：两个较大的掷骰都触及钳制，只有小掷骰落在它之下。

同样的模式也适用于其他大地图，且有直接的实际后果。在 Alps 上最大档是 185；大或中掷骰相乘至少 270，钳到 185，而 95 的小掷骰乘以 1.5 是 142.5 向上取整到 143，在钳制之下。所以 Alps 团队大厅在大或中掷骰上是 185、在小掷骰上是 143。在中东与 Two Lakes 上最大档是 170；大掷骰 170 乘以 1.5 是 255 钳到 170，中掷骰 130 乘以 1.5 是 195 钳到 170，小掷骰 85 乘以 1.5 是 127.5 向上取整到 128，这就是为什么表中这两张地图小掷骰团队大厅显示 128。关键结论是这些大地图上的团队模式现在稳定在高区间，常常在最大档或接近它，这让团队成为你想要一个大的、玩家充足的大厅时的强选择，因为不像自由对战的掷骰可能给你 105 的小大厅，The Box 上的团队模式无论掷骰如何都给你 158 到 210。这种稳定性本身就是一个决策输入：如果可靠的大大厅对你比自由对战掷骰的方差更重要，那大地图上的团队模式就是通往它的更可靠路径。

## 紧凑、拥挤，以及不变的地图

还有两套规模系统会与此变化交互，理清它们能防止最常见的混淆。第一是紧凑模式，本次 PR 未改变它。当一个大厅紧凑时，游戏取正常算法产生的规模，把它缩减为四分之一，所以紧凑大厅总是同一地图正常规模的一个小版本，不会重新遇到任何上限。实际要点是紧凑与此变化不冲突：一个紧凑的 The Box 大厅是 210 的四分之一，而不是一个被钳制的数字，[紧凑地图规模指南](/guides/map-size-compact-mode/) 涵盖了这种四分之一下法如何与地图空间交互。第二是拥挤修正器，它是个可掷到的加权修正器，会强制一个特定玩家数，但只在小地图上。它在该地图最大档不高于 60 人时触发，这描述的是小块、地薄的地图，它会把人数设成一个固定的拥挤值，而非让地块驱动的三档决定。这五张大地图从不会被拥挤处理，因为它们最大档远高于 60 阈值，所以对它们而言规模纯粹由地块驱动。理解这种分离很重要：拥挤修正是小地图获得大大厅的唯一方式，它和地块驱动的增大是完全不同的机制，所以不要把拥挤小地图与大地块富地图混为一谈。

第三也是最关键的范围内点是哪些地图完全不变。每张最大档本就低于旧 125 上限的排程地图——小岛地图、地薄的世界与区域地图——都不受影响，因为它们从未真正触及上限。它们的地块驱动三档都远在 125 之下，所以移除上限对它们的规模毫无改变。如果你在这些地图上排队，你的大厅看起来和过去一模一样。这正是指南反复回到那五张地图列表的原因：只有那五张你能看到差异，实际含义是你挑的地图现在就是决定你是否获得更大大厅的东西。公开浏览器仍会在每张卡片上显示地图、模式和当前人数，所以地图选择与掷骰共同决定你的体验，[公开大厅浏览器指南](/guides/list-lobbies/) 涵盖了在提交队列前如何读取这些卡片。

## 场景：The Box 上的大掷骰自由对战

考虑一个具体的 The Box 大掷骰自由对战，它现在以 210 名玩家打开，而非稳定版上从未能超过的 125。这是同样地块上多了 68% 的玩家，它以你可以规划的具体方式改变早期游戏。在 210 人的战线密布局中，地块分散在很多更多对手之间，所以早期阶段比 125 局更慢、密度更低：你与邻居之间有更多空间，这意味着最初几分钟感觉没那么致命，但也意味着你必须在战线开始收拢之前建立一条可防御的扩张走廊，因为在 210 人局里，同时威胁的总数高得多。位置课是选一条把你出生点连到明确扩张方向的地块通道，建一条细但连续的边界，并抵制早期宽大而薄地扩张的诱惑，因为在 210 人局里，薄的前沿是最先被挑掉的东西。经济课是金币收入现在必须支持一次更长、更有争议的扩张，而非快速推进，所以你想在投入兵力到战线之前拥有一个稳定的工厂与港口基地。这个场景迫使你做的决策是时机：在 210 人的 The Box 上，你比 125 局更晚投入战线，因为额外玩家意味着地图更多部分仍在争夺中，早期推进更可能被吸收。

玩家人数掩盖了另一个结构性差异。在 210 人下，地图被分成比 125 多得多的战线，所以单独看没有一条战线那么危险，但总压力更高，战线在地图上展开而非集中在一两条上。这意味着你的注意力被摊薄，而在 210 The Box 里杀死最多玩家的失败模式，是聚焦在一条战线上，同时另一条在另一侧两条地块处拿走你未设防的走廊。反制是把扩张保持为一条连续战线而非少数纵深推进，这样任何轴向上出现的新威胁都会遇到一道准备好的边界而非一条开放通道，并在一条新战线出现的瞬间就轮换你的预备队，而不是在已经失地后才反应。卡片上的读数是这一切的触发器：当你看到 210，你玩的不是旧游戏的放大版，而是一个不同的、更慢、更宽、战线更多的游戏，整个开局——走廊形状、建造顺序、投入战线的时刻——都应据此调整。如果你在卡片上看到 210，就更晚投入战线、持有更大预备队、保持边界连续而非单薄。

## 场景：The Box 上 158 的团队对战，对照自由对战

现在对照同一张地图的团队模式——它在 The Box 上小掷骰以 158 打开，大或中掷骰最高到 210——与自由对战。最根本的差异是团队模式在自由对战变化的地方是稳定的：The Box 上的自由对战可能因掷骰落到 105 人小局，而团队大厅至少 158。如果你的目标专门是玩一个大的、玩家充足的大厅，The Box 上的团队模式是更可靠的选择，因为 1.5 倍乘法加上钳制保证了一个高人数。战略纹理也不同。在 158 到 210 的团队局里，地图被队伍划分，所以战线数量比自由对战少，但每条战线的深度更高，因为每个队伍在共享位置后汇聚它的玩家。这意味着早期游戏不那么关于守住一条个人走廊，而更关于与你队伍的扩张方向对齐、并增援共享战线。经济取舍是你的金币现在服务于队伍节奏，所以喂给队伍推进的工厂密集型早期建造通常好过只保护自己角落的防御型建造。团队版本要警惕的失败模式是当你的队伍在另一条战线被推进时，把你的个人位置过度投入一条战线，因为每队更高的人数意味着一次错配会被整支队伍感受到。因此在 The Box 上选团队而非自由对战，是在可靠与结构上向自由对战掷骰的原始混乱让一步，当你想要大厅体验而不想让自由对战掷骰的方差决定地图规模时，这是正确的挑选。

两者之间的取舍，在你思考各自主张买什么时最锐利。自由对战买到了这次变化的完整分布：大掷骰给你 210 人的战线密布局及其多战线、慢扩张纹理，小掷骰给你 105 人的经典局，所以自由对战是你感受新分布两端、也是“大厅”最极致的地方。团队模式买到的是稳定：因为 1.5 倍乘法和钳制把人数保持在 158 到 210 之间无论掷骰如何，团队大厅从来不会是小局，而这个下限正是你优先要可靠大厅而非方差时的全部要点。玩法上的结构性差异是战线数量：一个 210 自由对战在地图上有许多短战线，而一个 210 团队大厅战线更少更深，因为玩家按队伍分组在共享位置后汇聚，所以单条战线即使总战线数更低也更激烈。如果你想以最极端形式测试新的大大厅行为，就在 The Box 上拿一个大掷骰自由对战。如果你想要一个每个会话都能依靠的大的、有结构的游戏，就选团队模式，因为在那里掷骰无法给你一个小局。

## 场景：Mare Nostrum 的 130 对照 Alps 的 185

最后一个场景比较两张处于这次变化不同位置的地图，以说明“大厅变大”不是单一体验。Mare Nostrum 的大掷骰自由对战以 130 打开，只比旧 125 上限多五人；游戏基本是一个普通大厅带一点提升，早期游戏、扩张节奏与战线数量都接近你从稳定版已知的 125。Alps 的大掷骰自由对战以 185 打开，比旧上限多 60 人，是一个真正不同的、更密的局，战线更多、早期阶段更慢，性格上更接近 210 The Box 而非 130 Mare Nostrum。这个比较迫使你做的决策是把地图匹配到你真正想要的大厅规模。如果你想要一个比之前略大但可管理的游戏，Mare Nostrum 的 130 是好选择，因为它仍接近熟悉的 125 体验。如果你专门想玩新的大大厅风格——带这次变化引入的更宽战线与更慢扩张——要瞄准的地图是 185 的 Alps 或 210 的 The Box，因为增大真正显现的是那些大厅。

中间选项是中东与 Two Lakes 在大掷骰上的 170，比旧 125 大但不如 Alps 或 The Box 极端。它适合想要明显大于稳定版但不想要完整 210 人战线密布局的玩家，因为 170 大厅比旧 125 战线多，但扩张不像 The Box 那样被拉得那么开。把这次变化的三层实用地想：Mare Nostrum 是“几乎没变”，中东与 Two Lakes 是“适度变大”，Alps 与 The Box 是“真正不同”。要避免的错误是预期大大厅却选到一张增大可忽略的地图：因为看到变化公告就排队 Mare Nostrum、得到一个 130 人的局会觉得没劲，而排队 Alps 得到 185 会觉得像新体验。地图是决定你是否拿到这次变化的控制器，所以要刻意挑选，而非假定每个大厅现在都更大。如果你不确定自己想要哪种规模，最稳妥的打法是先在浏览器里读卡片、看掷骰落定的实际数字，再判断这个具体大厅是否匹配你的目标然后提交，因为仅凭地图已不再告诉你你会得到的规模。

## 当更大的大厅让你破防，以及反制

更大的大厅并非自动更好，而存在具体的方式会让习惯旧 125 的玩家破防，每个都有具体反制。第一个失败模式是在 210 人局里过早投入一条战线。在地图上有更多玩家，反推可以从更多方向来，所以早期对单一区域的硬推，可能在一个 125 下不存在的第二条战线上被利用。反制是把扩张塑成不过度伸展于单一通道，并持有一支未投入的预备兵，能在一战打开时轮换到第二战线，而非把全部投入第一次推进。第二个失败模式是低估慢启动。地块富的大地图早期密度更低，所以最初几分钟感觉更慢，战线打开得比你习惯的旧 125 节奏更晚；玩家若照标准“扩张再推进”节奏冲，会在战线终于收拢时发现自己正扩张中被抓住。反制是把早期节奏放缓以匹配地图，先建稳定经济基地再投入，并把最初几分钟当作走廊建造而非战线打开。第三个失败模式是为目标选错地图，正如 Mare Nostrum 场景所示：预期大大厅却落到增大可忽略的地图。反制是在加入前读地图与卡片人数，想要大厅目标时排大地块富地图的队。这四个破防与反制都只在 v0.35 上适用；稳定版 v0.34.25 的大厅仍钳在 125，所以 210 或 185 的行为在那里尚不存在，在线上稳定服务器上围绕它做规划会是错误。

第四个把这些结合起来的破防是元层面的：假定这次变化让每个大厅更好或更具竞争性，而实际上它只改变了大地块富地图，且只在大掷骰与团队掷骰上。一个预期新行为却在 130 Mare Nostrum 排队的玩家，实际上根本没体验到变化；一个在 The Box 排队却落到 105 小掷骰的玩家，即便地图是变化过的两张之一，也根本没体验到它。对这个元破防的反制是把规模当作你实际在选的东西——而非地图——并在提交前读浏览器人数。版本边界是最后一个破防：稳定版 v0.34.25 上没有任何这种行为，所以 210、185、158 的数字仅存在于测试版，你围绕它们建立的的任何习惯——读卡、等大掷骰、偏好团队以换可靠大厅——是只在大厅达到线上服务器后才会兑现的习惯。现在围绕变化做规划是对的；期待它出现在稳定大厅上则不是。

## 挑选地图与模式的决策框架

把整个指南拉拢到一起，v0.35 上加入哪个大厅的决策归结为三个输入：你挑的地图、你挑的模式、调度器掷的骰，你控制前两个，游戏控制第三个。最清晰的规则是把地图匹配到你想要的大厅规模。如果你想要尽可能大的大厅，就挑 The Box 或 Alps 并拿一个大掷骰自由对战；如果你想要一个每个会话都能依靠的大大厅，就挑 The Box 的团队模式。如果你想要正常游戏，就完全忽略这次变化并在任何地图上排队，因为在小地图上什么都没动。如果你想要中间值，就在中东或 Two Lakes 上拿一个大掷骰换 170。对于模式，规则是大地图上的团队模式是通往大厅更可靠的路径，因为 1.5 倍乘法加钳制让人数无论掷骰如何都保持高，而自由对战是你想要方差与单玩家混战原始混乱时的选择。对于在加入前读某个具体大厅，动作是看公开浏览器中卡片的当前玩家数，它告诉你掷骰落在哪一档，然后判断该规模是否匹配你的目标再点击。而把所有串起来的版本边界是这些数字中的每一个——210、185、158 团队大厅——只存在于 v0.35 测试版；当前稳定版 v0.34.25 的大厅仍钳在 125，所以指南描述的是你只会在测试版达到线上服务器后才看到的行为，围绕它做的任何规划都应限定在该边界内。

把三个输入放进一条规则：地图设定上限，模式设定可靠性，掷骰设定实际规模，你控制前两个而游戏控制第三个。如果你想要最大的可能大厅，就挑 The Box 或 Alps 拿一个大掷骰自由对战；如果你想要一个每个会话都能依靠的大大厅，就挑 The Box 团队模式。如果你想要正常游戏，就完全忽略这次变化并在任何地图上排队，因为在小地图上什么都没动。如果你想要中间值，就在中东或 Two Lakes 上拿一个大掷骰换 170。而因为掷骰只在大厅打开后才可见，每种情况下的最后一步都相同：打开公开浏览器，读卡上的数字，确认规模匹配你的目标再点击。最后这一步是大多数玩家会跳过的，也是“我在玩我想要的大厅”与“我在玩掷骰给我的东西”之间的分界线。版本边界是框住一切的框架：这些数字中没有一个出现在稳定版 v0.34.25 上，所以指南是 v0.35 的规划，它描述的习惯是测试版上线后去养成和测试的，不是今天该在稳定大厅上预期的。
