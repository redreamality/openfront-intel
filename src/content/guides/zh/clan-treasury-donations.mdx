## 直接答案：金库是单向、仅限成员的捐赠

氏族金库捐赠是把你自己账号钱包里的货币转入氏族共享余额，而且是不可逆的：接口"永远不会把氏族余额退回给玩家"，对话框也用大白话告诉你同一件事——"捐赠是永久且不可退的。捐给氏族的货币永远不会回到你手上。"你从氏族界面打开弹窗，在两个独立的池子里选一个，输入一个整数，然后确认。两个池子分别是 `soft`（琥珀色的胶囊，你靠游玩赚来的货币）和 `hard`（绿色的钚，通常是花真钱买的预付货币）。每个池子都在氏族卡片和氏族弹窗上有独立的余额，每笔捐赠都会记进一个只有成员能看的历史，你随时可以查阅。这个操作是有门槛的：如果你不是这个氏族的成员，请求会返回 `403`，对话框会显示"你必须先成为氏族成员才能捐赠。"你不需要是管理员，只需要在氏族内部，所以这道门槛是成员门槛，不是权限门槛。

这是整个答案里最影响决策的部分，因为大多数玩家点进弹窗时脑子里想的是另一个功能。金库**不是**那种在游戏大厅里把金币或部队交给队友的局内盟友捐赠。两者是不同的文案、不同的界面、完全不同的决策，社区几乎每提到"捐给氏族"的讨论都会把它们混在一起。金库弹窗的标签是"把货币从你的账号转入氏族金库"；局内的文案是"捐赠""发送 100""发送 500""最大"。如果你正在决定是否按下金库按钮，真正重要的事实有四条而不是一条：它无法撤销；它是幂等的，所以断线不会让你重复支付；钚路径带有一条胶囊路径没有的额外警告，因为钚是真金白银；金额是弹窗在发送前会校验的整数。这篇指南的其余部分都是为了让你把正确的数字摆在面前，用你能承受得起损失的货币、深思熟虑地做这个决定，而不是凭手感。

## 金库到底是什么，不是什么

避免最常见的那个错误最干净的办法，是把金库和局内捐赠彻底分开，因为两者都用"捐赠"这个词，社区几乎在每个提到"捐给氏族"的帖子里都会把它们搞混。金库是一个局外、持久的功能。它随 v0.34.0 上线（提交 `0a4302a0`，PR #5041），在当前的 v0.34.16 版本中没有任何改动——那个版本是一个只改遥测的补丁，没有碰到这里的东西。它有一个专门的弹窗、一个只有成员能看的捐赠历史，以及一个氏族卡片和氏族弹窗都会显示的余额。余额是以十进制字符串而不是数字存储的，schema 里明确标注了这一点，因为它的值可能超过 JavaScript 能安全表示的最大整数；当氏族没有任何结余时它是 `"0"`。这个细节不是无关紧要的：正是因为它，你应该去读余额字段，而不是在脑子里对余额做算术。

局内捐赠是另一个功能。它是局内径向菜单里的 `donateGold` 和 `donateTroops` 操作，也就是团队攻略里教你狂点着送给前排或后排的那些。它们在一个游戏大厅内把金币或部队在玩家之间转移，大厅一结束就清零，和氏族卡片上的金库余额没有任何关系。i18n 文案让这个区分毫不含糊，而这正是你必须谨慎的原因：当某个帖子说"我捐给氏族"时，你现在必须追问它指的是两者中的哪一个，因为答案会改变你正在做的整个决策。局内捐赠是一个大厅经济操作，半衰期很短；金库是对共享余额的一笔持久投入，它的生命周期比任何单局都长。

第二个、更微妙的区分，是**余额**和**捐赠流水**之间的区别。捐赠接口只列出玩家做出的捐赠。schema 的注释明确说明，氏族的战利分成、管理员调整、退款冲正属于另外的流水原因，这个接口把它们排除了，所以捐赠列表的总和**不等于**氏族的真实余额。真实余额是氏族信息对象上的 `softBalance` 和 `hardBalance` 字段。在实际操作里，这一点只对应一件事：不要靠手算捐赠历史来推断氏族攒了多少。去读余额字段，把流水当作成员贡献的记录，而不是当作一个累计总额。

| 功能 | 金库捐赠 | 局内盟友捐赠 |
|---|---|---|
| 发生位置 | 局外，氏族界面弹窗 | 局内，游戏大厅径向菜单 |
| 转移的是什么 | 你账号的胶囊或钚 | 玩家之间的金币或部队 |
| 是否持久 | 是，直到被花掉 | 否，大厅结束即清零 |
| 是否限成员 | 是（非成员 `403`） | 否，任意大厅队友 |
| 货币 | `soft` 胶囊 / `hard` 钚 | 金币 / 部队 |
| 可否撤销 | 永不，不可退 | 谈不上"撤销"，只是随大厅结束 |
| 重试会重复支付吗 | 否，每次打开弹窗幂等 | 不适用 |
| 余额显示形式 | 十进制字符串（BigInt） | 局内普通计数器 |

## 什么时候捐赠才是对的

金库只有在一个真实且持续运营的氏族里才说得通，所以第一个过滤器不是货币，而是氏族本身。一个只有一两个互相加好友的玩家、没有 Discord、你一停玩就从排行榜消失的氏族，是单向捐赠错误的容器，不管你现在压着多少闲置盈余。社区讨论把这一点讲得很具体：能活下来的氏族，是那些通过 Discord 运营的、排行榜名次是胜负比而不是可以刷的点数、而且你能叫出其他成员名字并知道他们还在玩的氏族。如果你的氏族过得了这道关，下一个过滤器才是货币，而决策在这里真正分岔，因为两个池子的成本结构完全不同。

捐胶囊是安全默认，也应该是你捐赠的大头。胶囊是赚来的琥珀色货币；你靠游玩产生它，捐出一整块只是转移盈余，不会花掉任何你能再赚回来的东西。整数输入和"余额不足"的 `400` 错误是胶囊侧仅有的真实护栏，而一次错误的胶囊捐赠的代价只是个人经济慢一点，不是一个你填不回的窟窿。一条合理的胶囊规则是：只捐你本来就会让它闲置的盈余——也就是你这周不会花在自己升级上的那些胶囊——并且用一次性、深思熟虑的数字来捐，而不是一连串零碎的小额。一个干净利落的整数，比十几笔把"捐赠"和"浪费"界限糊掉的小额转账，更容易被氏族记账，也更容易被你自己证明是合理的。

捐钚是完全不同的物种，界面也对此直言不讳：钚（hard）路径带有一条胶囊路径没有的警告——"钚是预付货币。一旦捐出，无法退款、无法撤回、无法转回你的账号。"钚是你通常花真钱买来的绿色货币，所以捐钚等于把你已经付过的钱，花进一个你拿不回来、而氏族可能活不过你耐心的池子。唯一站得住脚的钚捐赠，是一次小额、深思熟虑、一次性的充值，对象是你已经验证过足够持久的氏族——是你真愿意在氏族下个月解散时彻底亏掉的那笔贡献。如果你在犹豫，决策会自己给出答案：拿不准就捐胶囊、不捐钚，因为胶囊可以补回来，钚不行。决策规则不是"捐不捐是好"，而是"我愿意亏哪一种货币，而这个氏族值不值得我亏"。

## 版本边界与已核验的部分

把版本边界说清楚，本身就是决策的一部分，因为金库很新，而相当多的社区内容早于它。捐赠弹窗、`donateToClan` 接口、只有成员能看的捐赠历史，是在 v0.34.0 里一起上线的；而当前版本 v0.34.16 是一个只改遥测、对它们没有任何改动的补丁。实际后果是一条硬线：只要你在 v0.34.0 或更新版本上，你就有完整功能，本指南的一切都适用于你的客户端；如果你在 v0.33 或更早版本上，你根本没有这个弹窗，那个版本上也没有金库可捐。社区里播放量最高的教程是 v27、v28 和 v31，这正是它们没有讲金库的原因——它们录制时功能还不存在。这个空白不是巧合，而是版本边界在起作用；它也是你不该信任任何早于 v0.34.0 的"金库"视频作为今天功能行为依据的原因。

在 v0.34.x 范围内，已核验的机制是开源客户端里的那些，它们是本指南的承重事实：单向不可退的转账、幂等重试、`soft`/`hard` 拆分、成员专属的 `403`、整数校验、以及余额不足时的 `400`。而**没有**出现在 v0.34.16 开源仓库里的，是服务端的花费路径——真正把金库里的共享余额花掉的那段代码。客户端定义了你怎么存入、余额怎么显示，schema 甚至点出了另外的流水原因（战利分成、管理员调整、退款冲正），但开源仓库并没有暴露氏族在局内*拿这笔货币去做什么*。这是本指南不会替你断言的那一件事，也是这个功能文档里诚实的缺口。

所以"金库到底在局内为氏族买到什么？"是这一件事，你应该去问你的氏族首领或在实战里去确认，而不是从一篇指南里想当然。这并不意味着金库没用或捐赠没意义——它意味着金库首先是一份社会和经济承诺，而局内效果是你需要本地验证的那部分。本指南里其余的一切都锚定在一个你可以去源码里核对的版本上；而那一个开放的问题，恰恰是你该去问自己氏族里具体的人的问题，因为共享余额有多清晰，取决于持有它的那个氏族有多清晰。把版本边界当过滤器、把花费路径当问题，你就不会基于一篇早于功能本身的教程去做捐赠。

## 场景一：稳定的排名氏族、充裕的胶囊、没有可省的钚

假设社区讨论里描述的氏族光谱的健康那一端：你所在的氏族有八个叫得出名字成员、一个 Discord、以及你能看到在一百多局里稳定上移的排行榜名次。比值稳定，成员是你叫得出名字的真人，首领你问就会答。你压着大约六千枚闲置胶囊——比你这周花在自己升级上的多——而你没有一枚愿意亏掉的钚。你打开金库弹窗，问题是拿这块闲置盈余怎么办。

决策很简单，你应该快速做完，因为充裕的赚来货币盈余，正是金库被造出来要吸收的那种状态。你把闲置胶囊一次性、用一个整数捐出去，而不是挤牙膏。整数输入正是为这个而存在的：一笔深思熟虑的转账，比十几笔小额更容易被氏族记账；而幂等设计意味着，即使你点下的瞬间断线，重试"重放最初的 201 而不会再多转货币"，所以你不可能不小心把那六千捐两次。你**不**碰钚池，因为你那里没什么可捐的；更重要的是，无论你有没有钚，决策规则都一样——当你有充裕的赚来货币盈余时，要捐的就是这种货币。捐胶囊的代价是下周个人经济慢一点，这没问题，因为那些胶囊本来就是闲置盈余，代价靠玩就能补回来。

点确认前的具体检查是：这是我这周不会花的盈余吗？如果是，就捐整块。如果你发现自己对这个数字犹豫，就把它减掉四分之一、剩下的下周再捐——金库是一个反复的决策，不是一次性事件，而一笔稍小的首次捐赠，是校准你对氏族实际用量的感觉更安全的方式。这个场景里要避免的失败，和不足捐赠相反：它把金库当成倾倒你其实需要用来升级的胶囊的地方，结果"闲置盈余"根本不闲置。如果那六千对你一笔计划中的升级是承重的，就捐你确实不会花的部分，剩下的留在原地。金库吸收的是真实的盈余；它不该制造赤字。判断盈余有没有用的一个好办法，是问自己：你想用这些胶囊买的那个升级，这周是否有时效？如果是，留着胶囊；如果它能等一周，盈余就是真实的，捐赠就是安全的。

## 场景二：一个崭新、未经验证的氏族，你被诱惑去捐钚

现在假设光谱的另一端：你刚加入一个通过 Discord 招募频道找到的氏族。它有三四个成员，排行榜上还没有真正的战绩，首领提过要攒钚去做点什么。你有少量钚——绿色的、真金白银的货币——而诱惑是"证明你的投入"，在它还没赢下那份信任之前，就早早就捐上一大块。

这正是界面在向你示警的那种情形，而正确的做法是刻意慢下来。钚的警告不是装饰；它是功能在告诉你，"不可退"这三个字在唯一一个池子里是真金白银，而一个崭新氏族，是把真金白银的捐赠放进去最差的容器，因为你捐进去的那份持久性还没被证明。社区讨论里满是这样的氏族：玩家一停玩正式游戏，它们就从排行榜上消失。给一个你还没看它打出足够多局、还没展现出会存在的未来的氏族捐钚，是一笔对尚未被展示出的未来的捐赠。在这里出错的代价不是经济慢一点，而是真钱，永久地从你账号流出，流进一个下个月可能就解散的池子。

具体规则是：在你看一个氏族在真实的一段游玩里保持稳定的成员和稳定的名次之前，不要给它捐钚。先做胶囊贡献，那里的最坏情况只是一个你能靠玩补回来的更慢的个人经济。如果这个氏族在未来几周里挣下了它的持久性、首领又为攒钚提出了具体、明确的理由，那才是小额、深思熟虑的一次性钚充值变得站得住脚的时刻——即便如此，数额也应该和证据匹配：一个稳定了两周的氏族得到的充值，应小于稳定了两个月的氏族。这里的失败不在于原则上捐钚；而在于*过早地*捐钚，凭投入的反射而非凭证据，捐给一个未经验证的容器。金库奖励的是那个让氏族先挣到接收预付货币资格的玩家，而不是那个凭第一印象把它前置的人。

## 失败模式与如何逐个反制

金库有少数几种出错的方式，而其中大多数靠习惯而不是靠设置来避免，因为失败面是玩家的判断，不是界面。第一种是重复支付的担忧，而设计已经替你处理了：每次打开弹窗时铸出一把幂等键，在这次打开内的每次提交都复用它，所以断线后的重试重放的是原始请求，而不是再转一笔货币。反制只是简单地信任重试——如果你看到"请求失败"然后重新提交，你没有重复捐赠，你也不需要取消并重开弹窗来求安全，因为重开才会铸一把新的键、从而有第二笔独立转账的风险。

第二种是余额不足的 `400`，也就是你在所选池子里输入了一个你其实没有的数字。弹窗会校验输入的形状，但真正的约束是你的钱包，而反制是先在正确的池子里读一下你自己的余额，因为胶囊和钚的余额是分开的，误读另一个池子正是这个功能会诱导的那类混淆。第三种是"非成员"的 `403`，社区撞上它是因为他们试图给一个自己其实不是成员、或成员身份已过期的氏族捐赠；反制是先决检查，因为你必须先成为成员，而加入通常是一个 Discord 步骤而不是一个局内按钮，所以一个 `403` 往往意味着那个社交步骤被跳过了。

第四种是货币混淆，也是最致命的一种：本想捐钚却捐了胶囊，或者把闲置胶囊捐给金库而其实自己升级需要它们，两者都真实发生、都会让你付出代价，反制就是决策章节里的那条硬规则——默认胶囊，只有刻意选择且氏族已证明时才钚。第五种是流水混淆，玩家拿捐赠历史求和来得到氏族余额，得到一个按设计就是错的数字；反制是去读 `softBalance` 和 `hardBalance` 字段，因为捐赠列表是成员贡献的记录、不是累计总额，schema 也明说另外的流水原因被排除了。第六种是版本错误，即信任一篇无法描述一个它录制时还不存在之功能的、早于 v0.34.0 的教程。这些全都是习惯而不是 bug，而那个习惯是：把金库当作一笔深思熟虑、小额、反复、胶囊优先的决策，而不是一个大手笔的一次性姿态。

## 模式、地图，以及金库在氏族生活中的位置

金库在狭义上是不分模式的——弹窗在每种游戏模式下都是同一个界面——但*捐多少*的决策并不分模式，因为共享余额的价值取决于氏族在局内实际在做什么。在 FFA 里，社区最核心的挫败是同一氏族、同一旗帜的玩家会抱团，而排行榜是一个比值；金库最有用的地方，是作为"会协同作战的氏族"的信号——一个可见且维持的共享余额，是一个一起玩的氏族的标志，而不是一个只在 FFA 里刷分的氏族。在人类对国家和团队模式里，局内盟友捐赠才是主导的经济机制，金库退居次要：共享余额更像社区纽带而不是杠杆，因为真正左右一个大厅的是局内的金币和部队捐赠，而金库是站在大厅背后的那笔常备承诺。

地图条件对金库本身的影响，不如它对"你愿意捐多少盈余"的影响大，因为金库是局外转账、地图永远不改变弹窗。地图真正改变的是你的胶囊收入，也就是你能承受捐出多少盈余。在你能快速清场、攒胶囊的地图和模式下，你能承受捐出的闲置盈余更大，所以一个更大的整数捐赠是可持续的。在你早期就死掉、产出很少的地图和模式下，盈余很小，正确的捐赠也就很小——一个你确实能承受得起的整数，不是一个掏空你自己经济的数字。模式和地图不是金库界面的输入，但它们是"你该输入什么数字"的输入，而纪律是让你的真实盈余、而不是模式的热度，来决定捐赠。

社区信号补齐了这幅图，因为金库在经济功能之前，先是一个社区功能。那些能活下来的帖子，是氏族通过 Discord 运营、排行榜被当作要守住的一个比值的那些；那些死掉的帖子，是真的关于 FFA 抱团和"氏族有什么意义"的那些，而在那类帖子里，金库是错误的答案，因为那里的问题不是缺少共享货币，而是缺少一个继续玩的共同理由。招募帖强化了先决条件：进入一个真正的氏族是 Discord 优先的一步；而那些高播放量教程则通过干脆不讲一个比它们晚的功能，把版本边界可视化了。结论是：社区已经把"在什么条件下一个氏族值得这笔单向捐赠"描述清楚了——持久的成员、一个 Discord、一个要守住的比值、一个继续玩的共同理由——而金库是你在满足这些条件之后去做的事，不是创造这些条件的事。
