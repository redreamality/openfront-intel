## 直接回答：没有"创建"按钮，你要么占下新 tag，要么被拦截

OpenFront 的任何位置都没有"创建部落"按钮，而这个缺失本身就是"我怎么建部落"的全部答案。部落形成于服务器认出你声称的部落 tag、且没有其他任何人持有它的那一刻。客户端在你进入对局前，通过 `ClanApi.ts` 中名为 `checkClanTagOwnership` 的函数检查 tag：它先向一个公共端点（`fetchClanExists`）询问这个 tag 是否已属于某个存活部落。如果 tag 是未知的，检查"失败放行"（fails open），你就保留它——这意味着你成了实际上的创建者：一秒钟前还不存在的部落，现在有了第一个成员，也就是你，一个 1 人部落的 leader。如果 tag 已属于某个部落而你不是其成员，同一个检查会设置 `tag_not_member` 错误并禁用对局，直到你加入该部落为止。这条规则在 v32 milestone 中作为 issue #3911 引入，于 2026 年 5 月 23 日关闭。tag 本身被限制为两到五个字母数字字符；被拒绝时游戏会告诉你确切原因，共有三条简短提示：一条对应过短，一条对应过长，一条对应非法字符。所以"建部落"不是填一张表格，而是你输入的 tag 与服务器已知的 tag 之间的一次碰撞测试，结果完全由你落在测试的哪一侧决定。在你输入任何东西之前，最值得内化的一个区分是：静默成功的路径和被拦截的路径跑的是完全相同的代码，唯一区别是你选的那个 tag 是否已存在。这就是为什么 tag 才是决策、而不是按钮，为什么接下来几节读的是客户端设置的错误状态，而不是去寻找一个根本不存在的菜单项。同一个所有权检查在你重新进入对局时也会运行——如果你输入的 tag 后来被别人占走，一个第一天还能用的 tag 可能之后突然不能用了，而正确的应对方式是同一套成员资格逻辑，而不是重打一遍你并不拥有的 tag。记住这一点：本指南中每条路径最终都落在两种状态之一——一个你能用其作战的 tag，或一个属于别人、你无法使用的 tag；剩下的内容就是一份落到第一侧、并识别第二侧的地图。

## 三条路径：自助创建者、被拦截的复用者、列表部落

第一条、也是最常见的路径是自助创建者。你输入一个全新的、有效的 tag，所有权检查在其背后找不到任何存活部落，检查失败放行，tag 就成了你的，随之诞生的全新 1 人部落的 leader 正是你。此时没有任何消息进入工作人员队列，创建时也不需要 Discord 链接，你一旦开始玩，部落就即时生效。这是回答字面意义上"怎么建部落"搜索的路径，也是游戏内体验围绕它构建的那一条。第二条路径是被拦截的复用者，这是大多数困惑玩家实际撞上的情况。你输入一个以为空闲的 tag，或者一个你在别处看到的 tag，结果它已属于一个你不在其中的部落；所有权检查随即设置 `tag_not_member` 错误，对局被禁用，在你成为该既有部落成员之前你无法继续。这是 #3911 tag 所有权锁定的直接效果：在此之前，新客户端更容易悄悄塞进一个已被占用的 tag；在此之后，复用已占 tag 成为一个明确的、被门控的状态，而不是一次静默碰撞。第三条路径是列表部落（工作人员创建的部落），它完全是另一种对象。这些部落出现在游戏内浏览器和领地列表中，各自带有名字、描述，通常还有 Discord 链接；它们是根据申请、在 Discord 中已有存在的前提下创建的，而不是玩家随手输入 tag 建出来的。列表部落是你在部落板块里浏览并加入的对象；自助部落则是你通过选一个未用 tag 建出来的。把这两者混淆是"为什么我建不了部落"类问题的最大来源：浏览器展示的是列表路径，而创建路径在你自己的 tag 输入框里悄然发生。加入与归属的完整说明见[加入与归属部落](/guides/clan-membership/)。下面的表格是最快分清你正站在哪一条路径上的方式。

| 路径 | 发生方式 | 你得到什么 | 什么时候用 |
| --- | --- | --- | --- |
| 自助创建者 | 输入一个全新的、未占用的有效 tag；所有权检查失败放行，你保留它 | 一个 1 人新部落，你是 leader，拥有仅 leader 的设置权限 | 你想要自己的部落，且不想走任何审批 |
| 被拦截的复用者 | 输入一个已属于你所在之外的部落的 tag；`tag_not_member` 禁用对局 | 在加入该部落或换一个 tag 之前什么都得不到 | 你想要那个特定部落，或误把已占 tag 当成空闲 |
| 列表 / 工作人员创建 | 根据申请创建，带有 Discord 存在，出现在浏览器和领地列表 | 一个可被发现、可加入的部落，带名字、描述和 Discord 链接 | 你希望其他玩家找到并加入你，而不只是拥有一个私密身份 |

## Tag 规则：两到五个字母数字字符，以及三条拒绝提示

所有部落路径都被同一个 tag 结构（schema）把关，所以 tag 是你必须先弄对的东西。规则由客户端中的校验函数与结构强制执行，背后有最小和最大长度常量，而它浓缩成一句话就是：有效的 tag 长度为两到五个字符，且只包含字母和数字。没有空格、没有连字符、没有下划线、没有标点；短于两个字符不行，长于五个字符也不行。当你弄错时，游戏不会显示笼统错误，而是显示具体原因——这些原因就是语言文件中定义的三条简短字符串：短于两个字符的 tag 会触发"过短"提示，告诉你必须是两到五个字母数字字符；长于五个字符的 tag 会触发"过长"提示，说不能超过五个字符；包含任何既非字母也非数字的字符的 tag 会触发"非法字符"提示，说只能包含字母和数字。这三条字符串是你唯一会收到的格式反馈，值得记下来，因为客户端拒绝的 tag 根本没有到服务器的第二次机会。实际含义是：tag 同时是你在所有列表、所有成员名单和所有对局内队伍显示中的部落公开标识。两个字母的 tag 在技术上合法，但对队友来说很难搜索；五个字母的 tag 是游戏会接受的最长值。因为所有权检查就跑在这个精确的 tag 上，你输入的 tag 与某部落已持有的 tag 之间一个字符的差别，就是"成为创建者"与"撞上 `tag_not_member` 拦截"的差别。把 tag 当作一个永久的、不区分大小写的公开名称来认领，而不是用完即弃的占位符——客户端这么对待它，服务器也是。如果你想要一个令人记住的身份，现在就在这两到五个字符的窗口内选定它；如果你想找到并加入别人的既有部落，同样要把 tag 打对——拼错一个字母，你就会从"加入"变成"被拦截"。下表列出了三种典型输入与游戏会显示的拒绝提示。

| 输入 | 违反的规则 | 游戏显示的拒绝提示 |
| --- | --- | --- |
| 一个字符，或什么都没输入 | 短于两个字符 | 过短：必须是两到五个字母数字字符 |
| 六个或更多字符 | 长于五个字符 | 过长：不能超过五个字符 |
| 任何既不是字母也不是数字的字符 | 非法字符集 | 非法字符：只能包含字母和数字 |

## Tag 所有权锁定：#3911 改变了什么，你为什么会撞上它

部落 tag 生命周期中最重要的规则变化，是随 v32 milestone 上线的所有权锁定，追踪为 issue #3911，于 2026 年 5 月 23 日关闭。在此变化之前，"这个 tag 是空闲的"与"这个 tag 已被占用"之间的边界在客户端侧执行得没那么干净，玩家更容易输入一个已被某个与自己毫无关系的部落使用的 tag，结果陌生人的对局会以该部落的名义出现。锁定把这种状态变成了明确的、被门控的拦截，而不是一次静默碰撞。按客户端所有权检查的实现，机制现在是一个两步序列。第一步：客户端调用报告"tag 是否已属于存活部落"的公共端点——tag 存在的响应会把检查导入所有权分支，tag 未知的响应导入创建者分支，而 null 或不确定响应会被保守处理，而不是失败放行。第二步：在所有权分支中，客户端检查你是否是已持有该 tag 的部落的成员。如果你是成员，检查通过，你像预期一样在该部落下作战。如果你不是成员，检查设置 `tag_not_member` 错误，对局被禁用，你无法用你不属于的 tag 进入对局。锁定的原因与每个共享身份系统的理由相同：部落 tag 是一个共享名字，放任任何人悄悄借用一个已占 tag，会同时破坏该部落所有人的名单、列表和对局内队伍显示。对你而言的实际效果是：你找到的"空闲 tag"如果有人已经在其下作战，就不再空闲了；游戏现在实质上是在告诉你"加入那个部落，或换一个 tag"，而不是让你继续碰撞。这就是为什么一个看起来有效且未用的 tag 会突然拒绝工作：它不是格式错误，而是成员资格错误，出口只有两个——加入该部落，或选一个真正空闲的 tag。

## 组队、FFA 与部落在对局中实际做了什么

当你持有一个有效 tag 之后，下一个问题是它改变了游戏里的什么，而答案在组队模式和大混战（FFA）中并不相同。在组队模式中，共享同一部落 tag 的玩家会被归为一个整体单位；当该部落作为一方作战时，结果以部落为单一结果呈现——这就是为什么一个部落的战史可以显示干净利落的一胜一负，即使多名成员同在一个大厅里。客户端的战史视图对此非常明确：在组队或人对国的对局中，当所有人都在获胜一方时，部落呈现一个结果；它刻意区分了"只有部分成员获胜"与"部落作为单一单位作战"这两种情况。在 FFA 和排位 1v1 中，逻辑翻转为逐玩家结果：在二十人大混战里，一名部落成员获胜并不等于部落获胜，服务器会为每个部落玩家盖上各自的单独结果，让战史精确统计谁赢了，而不是宣布整个大厅获胜。这就是对创建者至关重要的"FFA 例外"：大混战中的部落 tag 不会把你的队友组起来，它只负责识别他们；它也不会强制你与部落其他成员站在同一边。后果是：在分组有意义的模式里，部落价值很高；在你本来就单打独斗的模式里，它的价值就低得多。如果你建部落是为了打有配合的组队对局，tag 正在为你做真实的机械工作；如果只是为了打 FFA，tag 主要是一枚身份徽章和一份共享战史，而不是盟友。v36.7 版本还在部落界面增加了便利功能，它们不改变上述分组规则，但改变了你管理身份的方式：部落 Map 标签页现在可以全屏打开，带返回按钮和一个所有成员可见的侧边栏；名字字段旁的骰子按钮可以随机取一个名字，可偏好部落风格或匿名风格。这些是导航与命名上的便利，不是新的战斗加成——读版本说明时值得分清这一点，别把便利功能误读为数值变化。如果你想在固定小圈子里提前磨合，也可以看看[创建私人自定义对局](/guides/create-private-custom-game/)。

## 常见失败与各自的对策

大多数"我建不了部落"的求助帖都属于少数几种失败，而每一种都有专属对策，没有万能修复。第一种是格式失败：tag 一个字符、六个字符、或含有连字符或空格，游戏返回三条拒绝提示之一。对策很简单：把它缩短或延长到两到五个字符的窗口内，剔除非字母数字的每一个字符——结构不接受其他任何东西，对客户端拒绝的 tag 也没有变通办法。第二种是成员资格失败，这是锁定引入的那种：tag 格式有效，但已属于一个你不在其中的部落，`tag_not_member` 错误禁用了对局。对策二选一：通过浏览器加入那个既有部落——如果那确实是你想要的部落，这就是正确动作；或者选一个公共端点报告为"未知"的真正新 tag——如果你想的是自己的部落。第三种失败是路径混淆：你在浏览器里找"创建"按钮而找不到，因为浏览器只列出已存在的部落，而创建路径根本不使用浏览器。对策是停止找按钮，意识到把未占用的 tag 输入自己的输入框就是创建行为，浏览器属于加入路径而不是创建路径。第四种失败是不确定的检查：报告 tag 是否被占的端点返回 null 或不确定的响应，客户端保守处理而非失败放行，这可能让一个本应工作的 tag 看起来失效。对策是稍等片刻重试，或换一个 tag，因为不确定的响应是瞬态而非永久拦截，也是唯一一种不对应"你做错了什么"的失败。第五种失败是创建后的身份错位：你不断改 tag 或显示名，之前的对局、名单和列表不再对齐——这是管理问题，不是创建问题。对策是把 tag 当作永久不变，显示名则刻意地改，因为 tag 是所有列表、名单和对局内显示挂其上的稳定主键。这些失败的成因都显示在客户端设置的错误状态里，所以真正要练的技能是：读懂你正处在三条 tag 提示中的哪一条、哪一种成员资格状态，然后套用对应的对策，而不是去猜一个并不针对真实关卡的修复。

## 两个场景：单人玩家建五字母 tag，以及撞上已占 tag 的队伍

第一个场景：一个想要自己部落的单人玩家，选了五字母 tag "ZETA9"，从未被使用过。他把它输入部落输入框，客户端运行所有权检查，公共端点报告没有存活部落持有 "ZETA9"，检查失败放行，玩家保留该 tag。部落现在恰好有一个成员，这个玩家就是 leader，拥有后来成员没有的仅 leader 可及的设置权限，包括名字、描述、Discord 链接，以及控制谁能加入的开放开关。没有排队，没有审批，下一次玩家进入对局时，队伍显示上就是 "ZETA9"。这位玩家实际做出的决策有三个，值得点名：格式决策——把 tag 留在两到五个字母数字的窗口内；身份决策——接受五字母是游戏允许的最长值，且比两字母 tag 更容易被未来的队友搜索到；路径决策——选择自助创建者路线，而不是浏览既有部落。第二个场景：三人小队在第一天约定 tag "WOLF"，每人各输入一次。第一位玩家的检查在 "WOLF" 背后找不到部落，失败放行，他成为创建者。第二、三位玩家随后输入同一个 tag；等他们的检查运行时，"WOLF" 已存在而他们还不是成员，于是撞上 `tag_not_member` 错误，在被加入之前无法在其下作战。对策是：创建者打开部落设置，把部落标记为开放，两名队友用同一个 "WOLF" tag 通过浏览器加入；之后三人在组队模式下同属一个部落，战史把他们归为单一单位。这个场景撞到的决策点正是锁定要凸显的那个：tag 只在第一个人认领之前空闲，其余所有人都必须走成员资格。两个场景的对照就是整堂课：同一条检查代码，同一个 tag 输入框，差异只在于谁先到了。

## 模式、地图，以及什么时候建部落值得

最后一个决策不是"你能不能建部落"——你几乎总是能——而是对你这种玩法来说它值不值得。在大地图的组队模式中，部落价值很高：tag 把你和固定队友归到一起，战史把部落当作单一单位追踪，对局内显示让队友无需交换完整用户名就能找到彼此。在协调是主要杠杆的地图与模式上，部落提供的身份是真实资产，而 v36.7 的全屏部落 Map 标签页（带所有成员可见的侧边栏）让整个部落更容易指向同一个计划。在 FFA 中，算盘完全不同：FFA 例外意味着你的部落 tag 识别你、积累共享战史，但不会把你编进队伍，所以 FFA 里的部落主要是社交与身份结构，你得到的价值是名单、共享战史和固定队友互相认出彼此的能力，而不是机械优势。在最大的地图上，大厅能容纳非常多的玩家，此时部落的共享身份正是让一小撮固定玩家像一名协同玩家一样行动的要素——这正是部落被设计来服务的场景。诚实的边界是：部落不改变任何战斗数值、任何经济速率或任何地图规则；它改变的是你能和谁分组、战史里显示什么、以及一个队伍找到并协同自身有多容易。所以建部落的合适时机，是你有一群可重复出现的、你想识别并追踪的玩家；不合适的时机，是你期待 tag 本身让你变强。如果你的目标是一个可被其他玩家浏览加入的列表部落，而不是自助身份，那就走带 Discord 存在的列表路径；当你站在另一边时，[加入与归属部落](/guides/clan-membership/)会告诉你怎么加入。至于建了部落之后奖励怎么分，见[部落钚奖励](/guides/clan-plutonium-payouts/)。创建者路径、被拦截的复用者路径和列表路径各自回答"我怎么建部落"这个问题的不同版本，而唯一做不到的事是假装那里有一个按钮。没有按钮。有一个 tag、一次检查，以及关于你想站在三条路径中哪一条的决策——而这个决策就是全部。
