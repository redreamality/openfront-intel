## 北极星：让玩家感到“这里始终是最新的”

访问者应在 20 秒内知道三件事：当前版本最影响实战的变化、自己这一局该怎么做、答案最后何时核验。站点不以总页面数、覆盖所有实体或每日发布量作为增长指标。

优先观察以下结果：

1. 核心攻略是否明确显示适用版本、最后核验日期和本版本最重要的变化。
2. “Water Nukes 怎么用”“什么时候停止扩张”等问题是否落到唯一、直接回答问题的页面，而不是索引页。
3. 正式版本发布后，玩家影响摘要和受影响常青页是否在约定窗口内更新。
4. Search Console 的错落地、低 CTR 和重复意图是否减少。
5. Feedlog、Issues 和社区中重复问题是否被合并为选题并最终指向权威答案。

## 编辑原则

### 1. 一个版本系列，一篇玩家影响总览

- 不为 `v32.1` 到 `v32.18` 分别制造十八篇薄版本文。
- `/changelog/vXX/` 是该版本系列的玩家影响总览，吸收后续小版本中真正改变玩法的内容。
- 小修复只有在改变现有结论时才进入总览和受影响攻略；纯稳定性修复留在官方 Release 来源中。
- 当前 `v32` 总览已经覆盖 Doomsday Clock、贸易船增长、核弹速度、Defense Post 占领、retaliate、联盟时长、地图工具和 WebGL。后续版本继续沿用同一结构，不重新回到逐补丁扩页。

### 2. 先修主答案，再增加页面

- 能在现有主落地页补直接答案时，不新建页面。
- 新页面必须对应独立的玩家决策；一个搜索意图只能有一个主落地页。
- 速查页与教程页可以同时存在，但必须分工：`/shortcuts/` 负责找键，`/guides/hotkeys/` 负责实战工作流和故障恢复。
- Water Nukes 的直接答案必须在 `/guides/water-nukes/` 本文中，索引页只负责导流。

### 3. 从“为什么输了”组织内容

文章先回答局内决策，再给数字、公式和源码依据。默认结构是：

1. 40–80 words 的直接答案。
2. 适用版本、最后核验日期、本版本最重要的变化。
3. 正确做法与决策阈值。
4. 两个以上具体局势或地图场景。
5. 常见失败、对手反制和调整方法。
6. 来源与下一步阅读。

### 4. 不伪造视觉证据

没有真实可核验截图时，使用数据表、HTML/CSS 原生解释图、路线示意或决策图。不得生成看似真实的游戏画面来证明出生点、地形或操作行为。

### 5. 多语发布允许分批，但事实必须一致

- 英文是事实母稿和主要搜索入口。
- 中文是重点编辑版本，优先保证直接答案、术语和搜索意图自然。
- 紧急正式版本摘要允许先发布 en + zh；fr/de/nl 在事实稳定后分批补齐。
- 目标窗口：正式 Release 后 24 小时内完成 en + zh 玩家影响摘要，72 小时内完成受影响页面和其余语言。
- 数字、默认键位、版本范围和结论不允许因分批发布而漂移；`content-loop.md` 必须记录每个语种的状态。

## 内容架构与完成定义

### 新鲜度层

这一层负责建立“始终最新”的第一印象：

- 首页优先展示“最新版本变化”“第一次玩”“快捷键”“经济增长”，原始数字降为辅助入口。
- 每个正式版本系列维护一篇玩家影响总览，不按小版本拆页。
- 受影响的常青攻略正文顶部统一显示：适用版本、最后核验日期、本版本最重要的变化。
- 页面更新不是只改 `updatedDate`；必须说明哪条玩家决策发生了变化。

完成标准：访客无需翻到来源面板或页脚，就能判断答案是否适用于当前版本。

### 核心决策层

按真实需求和玩家价值排序：

1. 人口增长与部队甜区：何时停止扩张、保留多少兵、何时存钱。
2. 攻击比例：不同局势投多少兵，为什么兵多反而会输。
3. 快捷键与控制：速查页找键，教程页教连续操作和实战恢复。
4. Water Nukes：定义、触发、进攻、防守和常见误解全部在正文直接回答。
5. Doomsday Clock：宽限期、收圈节奏、部队/战舰衰减和撤退决策。
6. 出生点与边界形状：海岸、半岛、中心和瓶颈的具体判断。
7. 私人房设置：联盟时长、匿名名称、随机出生、Doomsday 等设置适合什么玩法。

完成标准：每篇只服务一个主要决策，并能从首页、相关机制页或相邻攻略获得至少两个自然入口。

### 地图试点层

不批量生成几十篇模板页。先验证五张差异明显的地图：Caribbean、Danish Straits、Venice、Yellow Sea、World Inverted。

每篇必须回答：

1. 更适合海战还是陆战。
2. 好出生点具有什么特征。
3. 最容易犯什么错误。
4. 哪些模式最好玩。
5. 中后期胜负通常在哪里决定。

完成标准：必须使用地图数据、可核验布局或解释图体现该地图的独特决策；若删掉地图名后文章仍可套到任何地图，则不发布。

## 当前战役：恢复“始终是最新的”印象

当前战役不是“继续扩页”，而是让版本总览、首页和常青攻略形成一条完整的新鲜度路径。除事实错误或新正式 Release 外，每日任务都应先推进本战役，再领取后续主题。

## 每日任务如何选，而不是机械地勾第一项

### 硬门槛

候选任务在进入每日执行前必须同时满足：

1. 有明确玩家问题和唯一主落地页。
2. 有足够的正式 Release、上游源码、生成数据或真实玩家反馈作为证据。
3. 能说明为什么更新现有页仍不够，才允许新建页面。
4. 属于当前战役，或属于允许打断战役的事实错误 / 正式 Release。
5. 有可验证的完成定义，而不是“增加字数”或“多做一页”。

### 优先判断

通过硬门槛后，用以下维度辅助判断，不按总分自动执行：

- 新鲜度风险：当前答案是否会让玩家做错决定。
- 玩家影响：问题影响多少局、影响是否直接。
- 已有需求：GSC、Feedlog、Issues 或社区是否反复出现。
- 复利价值：是否同时改善首页、内链、多个相邻页面或后续主题。
- 证据成熟度：事实是否稳定，是否适合立即本地化。
- 维护成本：是否会制造长期同步负担或薄页。

每日记录必须用两句话说明：“为什么今天做这个”“为什么其他高分项继续等待”。评分只能帮助编辑判断，不能替代判断。

### 允许的每日产出

每日运行不等于每日发新文章。合格产出包括：

- 完成一个主答案或一个受影响页面集的刷新。
- 为当前周目标建立可复用的来源包和决策大纲。
- 合并重复意图、修复入口或停止一个证据不足的选题。
- 核验发布后数据并决定继续、重写、合并或取消。

若当天没有足够证据或前置 PR 尚未合并，只更新研究结论和阻塞，不制造空内容 PR。

## 可持续内容循环

### 正式版本发布

- 24 小时内：确认 Release 正文不是 TEST，占用 `FRESH-01` 通道，发布简短的 en + zh 玩家影响摘要；若五语可在不延误的情况下完成，可以一次发布。
- 72 小时内：更新被影响的机制、快捷键和攻略页；补齐 fr/de/nl；在页面顶部写清版本与关键变化。
- 不为每个小修复新建文章；只有改变玩家决策的内容才进入版本系列总览或常青页。

### 每周

- 设定一个“玩家结果”，例如“玩家能判断何时停止扩张”，而不是“发布 population-growth 页面”。
- 最多交付一篇新的玩家问题或地图专题；其余工作优先刷新现有答案、入口和来源。
- 周末检查当前战役的退出条件，必要时调整 Next/Later，但不因一天的新关键词随意打乱路线。

### 每月

- 查看 Search Console 7/28 天趋势、Feedlog 票数与评论、GitHub Issues 和页面反馈。
- 以搜索意图合并 query，记录错落地、低 CTR、内容缺口和已经解决的问题。
- 从真实问题中选择下月主题，并明确哪些候选被拒绝及原因。

### 每季度

- 清理过时版本描述、合并重复页面、重写低点击入口。
- 检查核心攻略的新鲜度摘要是否仍可信。
- 审核地图试点是否值得扩展；没有证据时停止，而不是补齐数量。

## Feedlog 作为选题池

Feedlog 不只是“提建议”入口。玩家可围绕以下问题提交和投票：

- 我为什么输了？
- 这个按钮或设置是什么意思？
- 哪张地图不会玩？
- 哪条攻略已经过时或没有直接回答问题？

每周将真实帖子规范化为玩家问题，合并重复项，记录票数、评论数、受影响页面和当前状态。系统欢迎帖、无内容占位和无法复现的问题不进入选题池。

候选进入计划时，`content-loop.md` 记录 Feedlog 帖子链接和票数；内容发布后回链权威页面，并把帖子状态更新为已解答或需要继续验证。票数是需求证据之一，不是唯一排序算法。

## 明确不做

- 不追求每个单位、建筑和地图都有一篇薄页面。
- 不批量写开发者、源码或部署教程；除非 GSC 或玩家反馈证明有稳定玩家需求。
- 不追逐拼错的品牌词。
- 不把每个小修复变成独立版本文章。
- 不用总页面数、字数或“连续发布天数”作为增长指标。
- 不因为五语未能同日完成而延迟紧急 en + zh 版本事实；也不允许长期遗忘待补语言。
- 不为了填满每日任务而发布证据不足、与现有页面重复或无法维护的内容。

## 计划变更规则

以下情况可以立即打断当前战役：已确认事实错误、有真实正文的正式 Release、会让玩家按旧结论操作失败的上游变化。

其他变化只在每周校准或每月复盘时调整本文。调整时必须写明新证据、被推迟的计划项和新的退出条件；每日账本不能自行把临时发现升级为长期战略。
