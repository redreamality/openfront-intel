## Verified official sources

- [Official v0.35.4 release](https://github.com/openfrontio/OpenFrontIO/releases/tag/v0.35.4): current editorial boundary and release context, including the recent mobile attack-slider fix.
- [MapPlaylist at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/server/MapPlaylist.ts): regular public configuration sets overtime enabled when the mode is FFA. The source explicitly notes that this default has no public modifier badge. Special configurations are generated separately, so the guide does not claim that every possible lobby uses identical defaults.
- [Shared Config at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/packages/engine-lib/src/configuration/Config.ts): the Overtime defaults start at thirty minutes and drop two percentage points per minute in whole-point steps. Only enabled and startMinutes are wire-configurable. The article therefore says that private rooms can change enablement and start time, rather than suggesting hosts can freely change the decline rate.
- [InputHandler at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/InputHandler.ts): pointer movement, touch events, normal mouse-up handling, and the left-click-opens-menu preference are distinct states. The opening instructions explicitly separate mouse and touch instead of telling mobile readers simply to click an enemy.
- [ClientGameRunner at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/ClientGameRunner.ts): manual spawning selects valid unowned land during the spawn phase; normal land attacks require a valid available action and use the current attack ratio. The new summary does not promise that every map tile can be attacked or that random-spawn games allow manual selection.
- [ControlPanel at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/hud/layers/ControlPanel.ts): the initial attack ratio is 0.2, but user settings are restored. The visible current value is the instruction, not an unconditional promise that every new game starts at twenty percent.
- [WarshipSelectionController at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/controllers/WarshipSelectionController.ts): a touch on land emits the context menu event during play; during spawn it forwards the selection action. Water touches can instead select or move Warships. The quick-start text therefore says land tile rather than promising that every touch opens a menu.
- [UserSettings at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/UserSettings.ts): leftClickOpensMenu defaults to false. A reader with this option enabled needs a qualified explanation rather than a declaration that their controls are broken.
- [SinglePlayerModal at v0.35.4](https://github.com/openfrontio/OpenFrontIO/blob/v0.35.4/src/client/SinglePlayerModal.ts): single-player configuration supports difficulty selection and starts with Easy in its default options. Choosing a simple practice match is an editorial recommendation, not a guaranteed winning strategy.

## Content and interface decisions

The new FirstMatchQuickStart component appears before the long article body. It gives five concrete actions: launch practice, choose a spawn, read the attack ratio, make one expansion, and open the build menu after securing the core. Each instruction names both the action and the feedback the reader should inspect. The summary intentionally does not prescribe a universal opening percentage, a mandatory first building, or a fixed timer for every map. Existing strategic detail remains below it for readers who need the reasoning.

Mouse and touch instructions are displayed together without a JavaScript toggle. Both remain readable when scripts fail or are disabled. On small screens the cards stack rather than hiding either input method. The touch card links to the established localized mobile-controls article. The official launch link goes to the official game homepage; it does not invent a deep link that promises to open Single Player directly.

The four-step visual is explicitly labeled as a learning diagram rather than a screenshot. It illustrates the order of decisions with native HTML and CSS. No generated or reconstructed image is presented as an actual capture of the game. The diagram's text is localized in all five languages, and its numbers are decorative because the textual sequence is already available to assistive technology.

Each localized guide directory receives a prominent first-match link before its existing answer paths. Existing specialist routes remain available. This change improves the discovery of the complete tutorial without replacing all broad guide queries with a single article. The destination includes the first-actions anchor so the reader reaches the actionable opening rather than another catalogue.

## Long-form structure and preserved work

The initial worktree baseline contained many short third-level headings and several short second-level sections. Expanding every tiny question to four hundred words would make an already substantial tutorial less usable. Short steps are now paragraph labels, grouped beneath fifteen coherent second-level sections. The small learning-goal section joins the direct answer; the debrief joins mode adaptation; the next learning path joins the FAQ. Their text is retained rather than removed.

Old heading anchors are preserved using the same GitHub slugger implementation used by the Markdown ecosystem. This retains externally shared direct links to individual steps even though those labels no longer fill the generated table of contents. The retained second-level sections remain the navigable article structure, and each must independently pass the required minimum length.

The original working directory contained uncommitted first-match drafts from another activity. They were read only as context. No file in that original directory was modified or copied wholesale. Their useful correction about public FFA Overtime is included after tagged-source verification. Their broad claim that every public mode shares identical victory conditions was not adopted, because the new first-match summary does not need such a universal statement.
